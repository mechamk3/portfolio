## Portfolio structure
- Site copy lives in `src/content/{en,fa}.ts` (+ `hris/` for the case study); pages only read from there, so keep the dictionaries free of keys no page renders.
- Every page sits under `src/routes/$locale.*`; `/` redirects to the default locale (fa) and `__root` sets `lang`/`dir` from the locale param. The language switch is a client-side `Link` (no reload).
- Defaults are light, blue, Persian. A blocking inline script in `<head>` (`themeInitScript` in ThemeProvider) applies the saved theme/accent to `<html>` before first paint, so there is never a flash of the default; keep it in step with `applyToDocument`. ThemeProvider writes to `<html>` and localStorage directly when the visitor chooses (nothing is stored until then) and sets `data-switching` for two frames so every surface changes at once. UI that depends on theme/accent (icons, swatches) must read it through CSS (`dark:`, `var(--signal)`), not React state, which only syncs after hydration.
- Project cards are text-only (no artwork): `ProjectCard` shows meta, title, status, tagline, tech icons and the "Read more" button, three per row on large screens.
- The shared Backdrop supplies a quiet, token-based flat canvas to every locale page; keep decoration centralized rather than layering it into sections.
- The footer AccentPicker (swatches only; ThemeProvider `ACCENTS`, persisted in localStorage, applied as `data-accent` on `<html>`, blue is the unmarked default) re-themes the whole site: every palette color derives from `--h/--hs/--hg/--k` in styles.css, so never hardcode hues in components; `mono` sets `--k: 0`. Add a new accent as an `ACCENTS` entry, a `[data-accent]` rule and `footer.colors` copy in both dictionaries.
- Surfaces are near-neutral (soft charcoal in dark, soft paper in light, never pure black/white); only the signal colors follow the accent, so changing `--h/--hs/--hg` must never repaint the page. Sections share one canvas separated by hairlines (no alternating bands, gradients, grids, dots or hatching). Success, warning, and danger retain distinct semantic hues independently of brand accents.
- Home sections use the shared `Section` layout (sticky label column + content column, `max-w-6xl`); project cards are built by `ProjectCard` (the "Read more" button is the sliding-text signal button, keep it).
- Contact is its own simple section on the home page (`#contact`); the footer is the same plain bar (copyright, version, accent picker) on every page.
